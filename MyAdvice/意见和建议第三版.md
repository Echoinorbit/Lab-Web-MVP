对于项目的commit tree中，我觉得应该重新规划一下：
对于一个项目，他只有一个main分支，所以左侧的分支/作者就可以改成作者，其次是中间的提图谱/交消息合并成提交详情。其中合并详情应该是一整张图（即一整张画布）而不是类似于表格的格子全部分开了。然后对于“节点由作者维护；项目组长不能修改他人节点”改成“节点由作者维护；项目组中其它成员不能修改他人节点”。然后新增节点的默认父节点是最新的上一个人上传的节点。参考Vscode的Git Graph来做。
其中按照现在的提交方式进行提交，无论父节点在提交图中表达的方式都是在最顶上的，这个问题需要修复一下。同时删除列表显示方式。
然后在进度栏中进度填写的时候，无法保存草稿和提交进度报告。报错如下：Invalid `prisma.$queryRaw()` invocation: Raw query failed. Code: `N/A`. Message: `Failed to deserialize column of type 'void'. If you're using $queryRaw and this column is explicitly marked as `Unsupported` in your Prisma schema, try casting this column to any supported Prisma type such as `String`.`。
帖子评论功能仍然不完善，可以参考bilibili/Youtube的评论功能进行设计。用户可以发表评论，删除评论，对自己的评论进行评论，对别人的评论进行评论，而且可以再次进行这个循环。
